# Team construction and cell-entry context

This standalone issue212 component prepares source prerequisites for team-created
actors to participate in ordinary event1 cell-entry dispatch. It does not execute
triggers, fabricate placed-map rows, authenticate caller observations, or admit a
whole mission by itself. Root VM/world integration owns actual moved events and
transaction ordering. The [provenance record](../packages/sim/MISSION_TEAM_CELL_PROVENANCE.md)
separates reused source proofs, supplemental static evidence and explicit WebRA2 policy.

`compileMissionTeamCellSource({cells,actions,definitions,rules,mission})` requires
genuine cell, team-action and entity factories. It joins the exact binding object,
profile, mission, definitions and base world/model identities, owns and hashes the
mission bytes, and reconstructs source definition stages. The ordered RuntimeIni
pins remain supplied source-session trust; these labels do not authenticate
physical rules bytes. A fresh verified catalog supplies that separate boundary.

Every team action is retained. Future spawn archetypes are checked before births,
including type Cloakable, Passengers, both rank ability sets and locomotor. Initial
alive movable actors receive a separate type audit; initial structure provider
fields are retained even when unknown. The source requires the genuine traversal
retained by WorldContent, checks the selected flat movement cells, and rejects the
widened ground traversal for this narrower context. Original cell-source metadata
is preserved, including unsupported initial actors.

Consumers must require both `allRequiredConstructorsReady` and
`supportedWorldInvariantReady`, alongside complete original source/program closure.
Unrelated action/declaration diagnostics remain required. Known ordinary constructor
fields do not authorize transport, follower attachment, dynamic ownership, crate
collection, cloak providers, native automatic behaviors or other locomotors.

`compileMissionTeamCellContext({source,teams})` derives an owned actor array from a
genuine common team context. Initial actors retain their original cell actor row
identity. Constructed actors identify their birth record, action, team instance,
member slot and birth tick. Released actors remain represented through historical
birth records even after active team bindings disappear. No synthetic INI origin
is assigned. Unknown/unsupported actors remain visible and ineligible.

`missionTeamCellSourceContext` and `missionTeamCellContextData` expose same-realm
genuine references for root composition. JSON copies, proxies around brands and
caller-made effects are not capabilities. A structurally validated saved birth
history is still not an unforgeable record of past execution. Actual entries must
come from the root's current single-world transaction receipt.

The source caps 16,384 types, 2,048 actors, 4,096 actions, 256 catalogs, 262,144
references, 64 source stages and 16MiB mission bytes. Source indexing reserves
8,388,608 work from the total 16,777,216 ceiling for two fixed construction
counters, then divides the balance between seven configurable source-view, field
and indexing counters.
A lower source work cap must exceed that fixed reservation. Both original profile
fixtures pass at 8,395,216 and reject 8,395,215; a budget cannot borrow an uncharged
construction pass. Byte parsing/hashing
and nested node/field/history limits are separate resource units. Context indexing and owned output
traversal charge before operations against at most 262,144 work. Its private
`contextWork` permits root aggregate tick accounting. A sufficient lower transient
context budget produces the same public context and hash. Output serialization is
capped at 32MiB. Imported data descriptors and native typed-array accessors prevent
getter/proxy values from changing a validated input boundary.
