# Initial object combat-event dispatch

[Issue204](https://github.com/lictl/WebRA2/issues/204) joins initial object tags to
authoritative damage and destruction. The optional genuine source catalog adds
events6,7,44,48 to complete mission preflight. It never removes unsupported operations
to construct a playable source prefix. Neither original opening is fully admitted.

## Source and callback boundaries

The [source adapter](mission-object-events-source.md) retains every object, shared
tag group and recognized instruction with its exact operands. Event44 matches the
literal attacker house index. Events6/7/48 retain their numeric operands without
using them as selectors. Every selected source instruction must join the same
mission, trigger, opcode and parameters; copied catalog metadata cannot substitute.

Positive nonfatal health loss produces the supported6/44 subsequence. Fatal
infantry/structure loss uses6/7/48; initial ordinary units use7/48/6. Destruction
callbacks belong to the health-zero transition, before death animation completion.
The full native paths also contain unsupported threshold/other event kinds; these
remain whole-program admission failures. Hijacking, ownership credit overrides,
dynamic tags and special native damage contexts are outside this initial policy.

Repeating mode2 retains native StateB death latches for7/48. ResetTimers does not
clear them, so later dispatch through the same shared tag can see an earlier death
observation. Cell1 and attacked6/44 remain transient, as do the existing polling
predicates. Once mode0 does not accumulate these latches; mode1 remains unsupported.
Forcing, enable/disable, reverse trigger order and logical deletion retain their
existing VM policy. No physical object/tag detachment or pointer expiration is claimed.

## Retained health observations and transactions

The world privately retains each completed combat health application with its
tick, attacker, target, weapon, applied damage and before/after health. Zero damage
is distinguishable from a positive loss; missed impacts do not create a record.
These are engine facts, not native mission callback names.

Only the exact returned WorldStep and its genuine WorldModel can retrieve this
immutable record through worldStepCombatObservations. Editing or copying public
trace data cannot invent observations. Failed multi-tick calls publish neither a
new world nor observations. Existing public traces, world/model/save shapes and
numerical work accounting remain unchanged. Every retained record corresponds to
an existing bounded hit/trace operation; the list also has the world trace cap.

The compound model checks the complete original world join and requires supported
initial source context for every actor eligible under its genuine combat bridge.
All scenery and movement-only actors remain represented. It derives the callback
subsequence from its own private world step, requires positive actual health loss,
and uses the source actor's tag/owner/family identity. It does not turn the later
corpse/destroyed presentation trace into a second death event.

The optional phase policy is webra2-world-health-callbacks-before-scenario-poll-1.
Each tick advances the world, applies due VM flag inputs, delivers successful cell
entries, delivers ordered per-hit object callbacks, and then polls source scenario
bindings. This D03 phase preserves the engine's movement/combat order while placing
mission delivery after the world transaction. Native per-object interleaving,
native mutation during damage callbacks and universal timing equivalence remain
unclaimed. Models without object sources retain their existing phase and identities.

MissionLogic.stepObjectEvents accepts explicit generic callback data plus an
optional cell list for one tick. It cannot prove movement or damage. The compound
adapter never takes either list from a caller; only private world transitions reach
that path. The VM bounds callbacks to8,192 per call and charges source indexes,
validation and dispatch work. The compound checks the limit before appending and
shares its existing work, trace and presentation payload caps across every tick.
