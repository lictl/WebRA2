# M0 real SHP and palette sample

A bounded SHP(TS) subset decoded and displayed one **real 800×600 sprite** in
Chrome, using a palette independently paired through native static data flow.
This closes the non-media visual sample investigation in
[#38](https://github.com/lictl/WebRA2/issues/38). It does not implement a world
renderer, all SHP codecs, lighting, shadows, remapping or a playable game. No
retail pixels, palettes, screenshots or original program listings are published.

## Verified source and native pairing

The [input manifest](shp-sample-manifest.json) pins both ranges and the outer
`langmd.mix` SHA-256. The [reproducible report](shp-sample.json) is generated by the
existing verified source reader, checking the full root and each member before
decoding. Both identities were independently checked by the MIX worker.

| Member candidate | Ordinal / offset / bytes | SHA-256 |
| --- | --- | --- |
| GLSLMD.SHP | 1 / 372,322 / 481,232 | `cbe28febf98264f0956193e1edb07ab21116bf17e9e8143297d9322dd47b82c7` |
| GLSMD.PAL | 6 / 853,554 / 768 | `64e0d014ae537cb656e03fad9a94ee510ae1e6c7a6440ed1cd4263a193af4f12` |

Pairing is supported by more than filenames. The MIX agent's
[native metadata](shp-native-pairing.json) pins `gamemd.exe` SHA-256
`3e81a61775d2745d1dabe397325ef663cd994ffc194da4e998e3bf5d2d308600`
and the 371-byte function range at file offset/RVA 1,249,952, VA `0x5312a0`,
range SHA-256 `3a28e6c3b3501f884aa2ce11a4bc1878ef1519bf0aa8268fde670773637370bf`.

That range loads GLSMD.PAL, shifts each of its 256 RGB triples left two bits,
constructs/stores the palette converter, chooses GLSLMD.SHP unless a global value
equals 640, then supplies that shape and the same converter to the drawing helper.
The global's interpretation as screen width remains provisional. Literal locations,
call sites, source identities and pinned YRpp helper-signature references are in
the metadata. The raw listing remains private. This is strong evidence for this
specific loading/drawing path, not a universal palette-selection rule or proof of
native framebuffer colors after conversion, lighting and display processing.

## Decoder subset and uncertainty

The file has an eight-byte global header, one 24-byte frame record and a frame
at offset 32. Frame origin is (0,0), dimensions 800×600 and format byte 2. All
600 rows begin with a little-endian length of 802, followed by 800 nonzero index
bytes; the final row ends exactly at byte 481,232. The palette has exactly 768
bytes and all components are within 0–63.

The implementation adapts the pinned OpenRA header/offset/palette reference, with
explicit GPL provenance in [shp-PROVENANCE.md](../../packages/formats/shp-PROVENANCE.md).
The sources disagree in a way this slice does not conceal: OpenRA's format-2
branch reads one prefix outside its row loop, while EA/XCC's compressed-bit branch
uses a prefix on every row and zero-run interpretation. This actual sample has
per-row prefixes and **no zero index bytes**, so literal and zero-run interpretation
coincide after each prefix. The implemented subset requires each row length to be
width+2 and rejects zero-valued format-2 data as unresolved. It does not generalize
from this sample to zero runs, padding conventions or every format-2 file.

Implemented checks include the file/table limits, nonempty frame geometry,
per-frame data offsets bounded by the next distinct offset, exact row lengths,
truncation, frame index and six-bit palette limits. Formats 0/1/3/unknown, empty
frames and shared frame offsets fail explicitly. Odd dimensions and x/y placement
are preserved exactly; this diagnostic does not adopt OpenRA's even-dimension
padding. Input cap is 16 MiB, table cap 1,024 frames and dimension cap 2,048, with
at most 4,194,304 decoded indices for one selected frame. There is no all-frame
allocation and no decoded pixel array in the public report.

Palette channels use the observed native `component << 2` (0–252), with opaque
alpha. OpenRA's additional low-bit replication to 0–255 is deliberately omitted.
The subset has no transparency/remap/shadow policy; the real sample contains no
index-zero pixels. General SHP support remains a future renderer requirement.

## Independent byte result and actual browser result

Node and browser independently produced these exact decoded hashes:

| Output | Bytes / SHA-256 |
| --- | --- |
| Indexed frame | 480,000 / `dc0cffb28e774f9b34c27eb43540449866be869a9db0df6982f9bceb2a85c3d9` |
| RGBA frame | 1,920,000 / `3524b1710d1aeb7a5660f48ad137b257f423e3ecd901032bc011fea9e77654a6` |
| Expanded RGBA palette | 1,024 / `46ed5a5a4068617c689643f0ec0d919c47168cae100c126dafcf37c36180c3f9` |

There were 254 distinct palette indices, 481,200 consumed frame bytes and zero
trailing frame bytes. An independent Python row decoder reproduced these hashes
without importing the TypeScript implementation.

Actual Chrome **152.0.7977.83**, on the [recorded Mac](browser-feasibility.md),
selected the verified private SHP and PAL through native file pickers. Browser
source hashes and decoded hashes matched the Node report. At UTC
2026-09-09 15:08:11, local file reads took 6.7 ms, decode plus RGBA conversion
23.7 ms, and reads/decode/hashing through `putImageData` 32.9 ms. Owned input/output
buffers totaled 2,883,024 bytes, the Canvas contained 1,920,000 pixel bytes and
nonstandard JS heap telemetry reported a 33,103,919-byte point sample. These are
**not total or peak browser memory**; hashes/Canvas copies, GC and browser overhead
are excluded. Submission of a draw is not measured physical-display latency.
The four-browser load/memory investigation is reported separately by the media
slice; this SHP presentation was measured only in Chrome.

The agent visually inspected the actual decoded image in the browser, without
publishing its screenshot. Release cleared both file selections and reset Canvas
to 1×1 with Decode disabled. Private files and transcribed browser metadata remain
in ignored `local/shp-sample/`. No image is generated by a placeholder or a remote
conversion service. Native rendering/color equivalence still needs original-game
comparison; visual coherence alone does not establish it.

## Reproduce and validate

Use Node 24.20.0 with `npm ci`. The metadata command outputs no retail data:

```sh
node --import tsx tools/analysis/shp-sample.ts /absolute/path/to/game docs/analysis/shp-sample-manifest.json
node --import tsx tools/feasibility/shp-serve.ts
```

Open `http://127.0.0.1:8766/` and select private verified copies of the two member
ranges. Keep extraction under ignored `local/`, using `createVerifiedSourceReader`
with the committed manifest's expected hashes, and never commit those copies.
The server's four exact routes contain only HTML, CSS, JavaScript and the decoder
transformed from this repository's TypeScript source. Node's experimental
`stripTypeScriptTypes` transform is pinned by the Node version and emits a warning;
there is no browser TypeScript runtime or additional compiler dependency. The
server rejects POST, asset paths, traversal and wrong Host values; CSP disables
connections from the page. No selected file is sent to the server.

```sh
node --import tsx --test tests/formats/shp-ts.test.ts tests/analysis/shp-sample.test.ts
npm run check
git diff --check
```

Nine original synthetic tests cover row-prefix placement, every truncation,
resource/rectangle/offset errors, cross-frame overreads, unsupported records,
explicit palette RGB/alpha values, verified root/member mismatches, manifest caps,
deterministic metadata and omission of unrelated input fields. Full repository
checks, HTTP boundary checks and an independent private byte reproduction are
recorded in the linked PR. Public synthetic tests are not retail compatibility tests.
