# Constructed team actors and source cell entry

[Issue212](https://github.com/lictl/WebRA2/issues/212) composes the source team
transaction with initial mission cell tags. It requires both complete mission
preflight and an explicit genuine team-cell source capability. Unknown required
mission semantics continue to prevent execution.

`compileMissionWorld` accepts optional `teamCells` only when its program has the
exact same genuine cell-entry and team-action source catalogs. Both complete
future-constructor eligibility and the supported world invariant must pass before
an empty runtime can start. The world-content factory privately retains the exact
traversal it consumed; copied metadata or a claimed traversal hash is insufficient.
The source rules/AI import trust boundary remains documented by the component.

For each tick the compound adapter:

1. Applies due team requests and advances controllers and their common world once.
2. Reconstructs the eligible initial and historical constructed actors from that
   genuine runtime's history, including actors released from a team.
3. Delivers successful `movement/moved` transitions, in world trace order, to source
   cell bindings, then polls scenario bindings in the same VM invocation.
4. Derives ordered next-tick team requests and presentation requests from its own
   private VM effects.

Birth on a tagged cell, reservations, progress and arrival without movement do not
produce a cell-entry event. Source country/house selectors continue to use the
entrant's supported original ownership. A released actor can later enter a cell
through an admitted player command; its constructor provenance does not disappear
when its controller is removed. This is the explicit WebRA2 phase policy
`webra2-world-team-cell-events-before-scenario-poll-1`, not a claim that native
callbacks have identical timing inside each object's update.

`MissionLogic.stepTeamCellEntries` accepts the genuine context separately from the
observation list. It validates exact program/source joins before using the dynamic
actor lookup. Direct VM observations remain explicit data and do not prove movement.
The compound API accepts host commands and flags only, and obtains observations
from its private, genuine single-world-step result. The original `stepCellEntries`
method continues to authorize initial actors only.

Completed checkpoints need no saved event queue or caller actor-context authority.
They retain the common team history/world, matching VM clock and source identities.
Restore validates the history and rebuilds context; replay rederives entries from
movement. The optional capability's source hash and phase policy distinguish its
compound model. Existing no-team and no-cell model/save shapes remain unchanged.
Source/context limits bound indexing and output; tick work charges context creation,
world-event scanning and VM work. As with existing compound save validation, bounded
checkpoint reconstruction is separate from execution work. Failure returns no
partial world, VM, team or presentation state.

Dynamic object combat callbacks, changed ownership, transports, follower attachment,
bridge movement, cloak-provider mutation and complete native campaign execution
remain separate work. The source capability is scoped to its documented constructor
and supported transition conditions; it does not grant automatic AI or native
allocation closure.
