# Mission team actions in the common world

Tracking: [issue210](https://github.com/lictl/WebRA2/issues/210) /
[PR211](https://github.com/lictl/WebRA2/pull/211). This is a campaign foundation;
neither original opening mission is fully playable. Source interpretation is
recorded in the [source report](mission-team-action-source.md) and the shared
controller in the [runtime report](mission-team-runtime.md).

## Complete source authority

The optional mission VM preparation takes a genuine team action source joined to
the exact source binding catalog. All original action4/7/80 occurrences, effective
team/script/task-force definitions and diagnostics remain represented. Exact
instruction, trigger, opcode and all seven operands must agree. Missing programs,
ambiguous catalogs, automatic behavior and uncovered definitions keep the whole
program unavailable. A successful isolated team selection cannot grant mission
authority.

Large retained declaration arrays are compared against the genuine source shape
using descriptors, preserving every field and order without increasing the smaller
simulation-save JSON limit. The source compiler bounds that shape. No supplied
getter is needed for this comparison. The existing VM diagnostic cap receives a
single catalog-closure diagnostic; the full original source ledger remains available
in the team catalog.

The VM emits team requests using its saved global effect order. Repeated forced
calls to one instruction have different effect orders, and the remainder of an
already entered action list remains ordered after trigger deletion. Coverage labels
these as effect-only requests. The flag-only replay entry point rejects team
programs because it cannot execute their world consequences.

## One world transaction

The optional `webra2-world-team-actions-next-tick-1` policy runs due team requests,
controllers and the common world once, then polls the mission VM. Newly emitted
requests are due at the following tick. This is an explicit WebRA2 phase choice,
not proof of native scheduling equivalence.

The compound constructs receipts only from its own VM invocation; host admissions
contain commands and flags, with no team receipt or effect list. The common
runtime arbitrates all recruitment and reinforcement claims together, including
whole-force claims, stable ordering and retries. Team-controlled actors reject
competing host commands. Source constructor rows remain distinct from placed rows.

A completed compound checkpoint retains request identities, claims, controller
state and release/Flash history. Its outer world must exactly match the nested
team world, and all three clocks agree. Request orders precede the VM's next effect
order and emission ticks precede its next tick. A prepared team candidate is not a
completed compound boundary. These are structural source checks, not cryptographic
proof of every prior transition.

Each tick has one genuine underlying world transition. Complete batches and replays
return a candidate only after commands, requests, world, VM, presentation and limits
all pass. Trace accounting includes team requests, orders, controller events and
world events. Destination planning receives the remaining aggregate budget before
navigation; visits, queries and expansions count together. Exact frozen prepared
plans retain private roster identity to avoid duplicate navigation computation.
Copied or serialized plans still recompute and compare.

Text/camera/radar requests can share the VM's global order and saved presentation
cursor. Initial actor cell/object catalogs are explicitly refused with the team
runtime until dynamic actor callbacks are implemented. Combat and infantry subcell
models remain outside this common runtime's source authority. No initial actor
adapter is silently extended to constructed actors.

## Validation

The composed full check passes1,197 public tests. Original fixtures cover both profiles, mixed4/7/80 claims, next-tick timing,
competing recruitment/retries, held Sleep, movement/Flash/release, forced repeated
instructions, deletion, interleaved localized text, saved queued requests, every
completed restore boundary, batch/replay equivalence, ownership conflicts, forged
identities, dynamic context refusal and late resource rollback. A large original
script corpus verifies source comparison beyond the save serializer's node cap.

An independent coordinator differential against merged main209 preserves64 legacy
world models,1,536 ticks and3,392 exact comparisons across models, work, effects,
checkpoints, batches and replay, including optional cue/cell/object contexts.

Private installation preparation is separate from those behavior tests. The
[aggregate preflight census](analysis/mission-team-dispatch-census.json) records a
fresh438-file import and complete VM coverage for both openings. Both authorities
remain null with254/461 required diagnostics;12/9 individual team actions are
admitted. Source-level counts, native static ranges and raw comparisons are in
the separate source report; common runtime200/128-tick private outcomes are in its
report. No source bytes, geometry, retail saves, screenshots or audio are published.

Reproduction: use the pinned Node runtime and `npm run check`; focused tests are
`node --import tsx --test tests/sim/mission-team*.test.ts`. Private coordinator
preparation is in ignored local/worktrees/mission-team-actions/local/probe210.mjs
and its local/team210 outputs, with verified on-device archive/source reads.
